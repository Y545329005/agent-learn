# agent-learn

> Give your AI coding agent a memory that survives across sessions and projects.
>
> 让你的 AI 编码助手拥有跨会话、跨项目积累经验的能力。

一个最小机制：把「每次会话都要执行的规则」放进项目的常驻指令文件，把「证据、日期、排错史」放进项目自己的证据文件，把「凭据」永远排除在对话之外。

由真实项目复盘提炼，经过三次证伪筛选——**只保留跑通过的部分**。

---

## 它解决什么问题

AI 编码助手每次打开新会话，都是失忆的。你上一次踩过的坑、定过的规矩，它不会再记得。常见的应对是堆一个巨大的 `AGENTS.md`，结果它会膨胀、漂移、最后没人维护。

本项目提供一套**三层分工**的落地方案：

| 层 | 放什么 | 为什么 |
|---|---|---|
| **常驻指令面**（`AGENTS.md` / `CLAUDE.md`） | 规则 + **反例边界** | 每次会话自动注入，必须精简 |
| **证据文件**（项目内的日志/归档） | 数据、日期、命令数、排错史、待办 | 只在需要时查，不进常驻面 |
| **不进任何文件** | 口令 / API key | 用 `set-env` 盲输写入 `.env` |

## 快速开始

### 1. 安装 skill

```bash
git clone https://github.com/Y545329005/agent-learn.git
cd agent-learn
./install.sh                 # 默认安装到 opencode
./install.sh --claude        # 同时安装到 Claude Code
./install.sh --codex         # 同时安装到 Codex
./install.sh --all           # 全部
```

安装后重启你的 Agent，`agent-learn` 会出现在 skill 列表中。

### 更新到最新版（已安装过的机器）

```bash
cd agent-learn
git pull
./install.sh            # 用与首次安装相同的参数重跑
```

`install.sh` 每次都是「删旧目录 + 拷贝新版」，所以**重跑即升级，无需先卸载**。
若首次装到了多个 Agent（如 `--all`），更新时带上相同参数即可。

### 2. 在日常对话里使用

不用记命令，说人话即可：

| 你说 | 会发生什么 |
|---|---|
| 「复盘一下」 | Agent 提炼这次会话的教训，**先给你草稿**，你确认后才写入 |
| 「这个记下来」 | 同上，直接进入规则草稿 |
| 「这属于通用还是项目？」 | Agent 按分层判定告诉你该写到哪里 |

### 3. 凭据永远盲输

```bash
./bin/set-env ~/myproject/.env DB_PASSWORD API_KEY
```

- 逐项盲输（不回显、不进 shell 历史、不进命令行）
- 写入 `KEY=值`，权限强制 `600`，临时文件 + 原子替换
- **非终端环境直接拒绝执行**（exit=2）——防止口令进入对话记录或会话数据库

配套约定：读取该文件时用**逐行解析**，不要 `source`（口令含 `$`、空格、`#` 时会被 shell 展开）：

```bash
while IFS= read -r _line; do
  case "$_line" in ""|'#'*) continue ;; DB_PASSWORD=*) DB_PASSWORD="${_line#DB_PASSWORD=}" ;; esac
done < "$ENV_FILE"
```

## 核心方法论

### 分层判定：一条经验该放哪

| 情况 | 去处 |
|---|---|
| 只适用于某个项目（含路径、地址、账号、业务规则） | 写进**那个项目**的常驻指令面 |
| 在 **≥2 个项目**独立验证过 | 才允许写成通用约定 |
| 一次性事件、数据、日期、排错史 | 进**该项目的证据文件**，不入规则 |

### 常驻面放什么、不放什么

- ✅ **保留**：规则本身 + **反例边界**（帮判断「何时不适用」的案例）
- ❌ **移出纯溯源**：编号、日期、会话号、命令数——归档里已有
- ❌ **移出可枚举参考**：文件树 / 清单——永远追不上，且会被当成权威地图误用

### 人工闸门

**规则只能由人写入。** Agent 可以提议、可以起草，但不能自动修改常驻指令面。

## 已知的反面（别再试了）

这些方向已经过实测证伪，写在这里是为了让你不必重走：

- ❌ **自动捕获工具失败事件**当学习信号——精度约 5%：绝大多数失败是环境脆弱性（网络、SSH、权限）或本就该非零的退出码；跨会话的行为性失误复现 ≈ 0
- ❌ **状态机 / 标签 / 编号 / 检索引擎 / 向量库**——清单会在数十条量级失能，并制造持续的治理负担
- ❌ **自动修改常驻指令面**——规则必须由人确认
- ❌ **照搬另一个项目的文件结构**——判定可以通用，实现必须各算各的账

## 实测效果

| 场景 | 效果 |
|---|---|
| 一个运维部署项目 | 完成同一任务所需命令数 **499 → 62 → 9**；凭据零泄漏 |
| 一个数据分析工具项目 | 常驻指令面从 13.6 KB 精简到 11.7 KB，并修正了漂移的文件树 |
