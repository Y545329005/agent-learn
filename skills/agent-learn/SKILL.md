# agent-learn：经验怎么沉淀

让 AI 助手的经验跨会话、跨项目保留下来。核心是**三层分工**。

## 先判定：这条经验属于哪一层

| 情况 | 去处 |
|---|---|
| 只适用于某个项目，且**改变决策、不可机械核对**（账号归属、业务口径、项目规则） | 写进**那个项目**的常驻指令面（`AGENTS.md` / `CLAUDE.md`） |
| 在 **≥2 个项目**自然验证过 | 才允许写成通用约定；**人工促成的证据点不计入** |
| 一次性事件、数据、日期、排错史 | 进**该项目的证据文件**，不入规则 |

⚠️ **可机械核对的事实（路径、文件树、入口地址）不要写进常驻面**——交给工具去查（`ls`、`git`），
写了必然过期。常驻面只收「会改变决策、又无法自动核对」的内容。

⚠️ **证据文件的命名与位置由项目自定，不要照搬。**

先看该项目有没有现成的证据归档目录（如 `docs/`、`archive/`、`CHANGELOG`、项目自有日志）；
有就复用，没有才新建一个，名字由用户决定。

**把别的项目用过的文件名拷进无关项目 = 制造「第二个 docs 系统」。**

## 常驻面放什么、不放什么

- ✅ **保留**：规则本身 + **反例边界**（帮判断「何时不适用」的案例）
  例：「封顶后 22% 标的挤在 100 分」——这种数字限定条件留下了才有用

- ❌ **移出纯溯源**：编号、日期、会话号、命令数——归档里已有，常驻面重复只是负担
- ❌ **移出可枚举的参考**：文件树 / 清单——永远追不上，且会被当成权威地图误用
  （实测：某项目文件树声明 28 个文件，实际顶层 45 个，大量未声明）

## 流程

1. **触发**：用户纠正、返工、同类错误第二次出现时 → 做一次复盘
2. **产出规则**：提炼成「每次会话都要执行」的结论，**先给用户草稿**
3. **证据分离**：日期、数字、根因、排错史 → 项目的证据文件；规则行内只留指针
4. **人工闸门**：**规则只能由人写入**，Agent 不自动修改常驻指令面
5. **回检与退役**：下次同类触发时，先核对上次规则是否真的降低了该类错误
   （如部署命令数 499 → 62 → 9）；**无效果或只增摩擦的规则应退役**，不留「加了就没人删」的规则
6. **凭据永不同路**：口令 / API key 一律用 `set-env` 盲输写入 `.env`；
   **禁止内联进命令行、禁止发进对话**（命令行会进 shell 历史、日志、进程表）

**跨项目任务**（工作目录与目标文件不属于同一项目）：先读目标项目的常驻指令文件
（`AGENTS.md` / `CLAUDE.md`，有哪个读哪个）再动手——工作目录不变时规则不会自动到位。

**新项目首沉淀**：第一次要写规则时，先问用户「要不要为此项目建常驻面 / 证据文件、叫什么名字」，
不照搬任何已有项目的文件名。

## 明确不要再做的（已被实测证伪）

- ❌ **自动捕获工具失败事件**当学习信号 → 精度约 5%：绝大多数失败是环境脆弱性
  （网络、SSH、权限）或本就该非零的退出码；跨会话的**行为性**失误复现 ≈ 0
- ❌ **状态机 / 标签 / 编号 / 检索引擎 / 向量库** → 清单会在数十条量级失能
  （编号冲突、僵尸行），并制造持续的治理负担
- ❌ **自动改常驻指令面** → 规则只能由人写入
- ❌ **照搬另一个项目的文件结构** → 判定通用，实现各算各的账
- ❌ **切换 Agent 时不检查指令面**：不同 Agent 读不同的常驻文件
  （Claude Code → `CLAUDE.md`；Codex → `AGENTS.md`；opencode → 两者）。
  切换后若新 Agent 不读原文件，**全部规则静默断线**
- ❌ **同一事实留两处人工副本、又不加同步触发器** → 必漂移
  （实测：cjq 文件树声明 28 实际顶层 45；本项目 README↔SKILL 流程 4 步 vs 6 步）。
  做法：**单一事实源**（只留一处，其余放指针或软链），或加**同步触发器**（脚本自动同步）
